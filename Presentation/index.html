The Security Landscape

Why do we need a new systems language?

  • The 70% Rule: Microsoft and Google report that ~70% of high-severity vulnerabilities are due to memory safety issues.
  • Legacy languages (C/C++) rely heavily on developer discipline and manual memory management.
  • Notorious CVEs (e.g., Heartbleed, Baron Samedit) stem from buffer over-reads and heap overflows.
  • Rust guarantees memory safety at compile time, preventing costly breaches.

Session 1: Core Concepts

Understanding the foundations of memory and legacy code limits.

Limitations of C/C++

  • Memory Management: Manual malloc/free leads to buffer overflows, use-after-free, and double free bugs.
  • Data Sharing: Unrestricted pointer access causes data races in concurrent environments.
  • Legacy Tools: Valgrind, ASan, and MISRA catch bugs at runtime or via linters—often too late in the development cycle.

The Heart of Rust

How Rust achieves memory safety without a garbage collector.

Ownership & Borrowing

Rust's unique approach to memory without a garbage collector.

  • 3 Rules of Ownership:
    1. Each value has exactly one owner.
    2. There can only be one owner at a time.
    3. When the owner goes out of scope, the value is automatically dropped.

  • Move Semantics: Passing a complex type (like a String) moves ownership, making the original variable invalid. This prevents Double Free bugs.
  • Borrowing: You can have many immutable borrows OR one mutable borrow, preventing data races at compile time.

Rust is foundational for critical infrastructure.

  • Regulatory Mandates: The US White House, CISA, and NSA are increasingly advising the shift to memory-safe languages.
