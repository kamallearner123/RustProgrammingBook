Session 1.3

C/C++ in the Wild

C and C++ are the backbone of modern computing, but their unmanaged memory model creates a playground for hackers. Before seeing how Rust solves these issues, let's test your ability to spot vulnerabilities in standard C code.

Image 2: C/C++ in the Wild

Vulnerability Challenge

Look at the 10 code snippets below. Can you guess what the vulnerability is before revealing the answer?

1. The Classic Mistake

#include <stdio.h>

void get_password() {
    char password[16];
    printf("Enter password: ");
    scanf("%s", password);
}

int main() {
    get_password();
    return 0;
}
Program 5: 1. The Classic Mistake
Reveal Vulnerability Stack Buffer Overflow. The gets() function reads from standard input until it sees a newline, completely ignoring the 16-byte limit of the buffer. An attacker can input 500 characters and overwrite the function's return address, taking control of the program.

Extended: Buffer over flow

#include <stdio.h>
#include <string.h>

void get_password()
{
    struct {
        char password[16];
        unsigned int guard;
    } data;

    data.guard = 0x12345678;

    printf("Before overflow:\n");
    printf("  password = %s\n", data.password);
    printf("  guard    = 0x%08X\n", data.guard);

    printf("\nEnter password: ");

    /*
     * Deliberately unsafe:
     * allows more than 16 bytes to be written.
     */
    scanf("%s", data.password);

    printf("\nAfter input:\n");
    printf("  password = %s\n", data.password);
    printf("  guard    = 0x%08X\n", data.guard);

    if (data.guard != 0x12345678)
        printf("\n*** BUFFER OVERFLOW: guard was corrupted! ***\n");
    else
        printf("\nGuard is unchanged.\n");
}

int main()
{
    get_password();
    return 0;
}
Program 5: Extended: Buffer over flow

2. The Math Trap

#include <stdio.h>

void transfer_funds(unsigned int amount) {
    unsigned int balance = 100;
    if (balance - amount >= 0) { // Check if we have enough
        balance -= amount;
        printf("Transfer successful!\n");
    }
}

int main() {
    transfer_funds(500);
    return 0;
}
Program 6: 2. The Math Trap
Reveal Vulnerability Integer Underflow / Logical Flaw. Because balance and amount are unsigned int, they can never be negative. If amount is 500, 100 - 500 wraps around to a massive positive number (e.g., 4294966896). The >= 0 check is always true!

3. The Ghost Pointer

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main() {
    char *user = malloc(100);
    strcpy(user, "admin");
    free(user);

    // ... later in the code ...
    printf("Welcome, %s\n", user);
    return 0;
}
Program 7: 3. The Ghost Pointer
Reveal Vulnerability Use-After-Free (UAF). The memory was freed and given back to the OS. Between the free() and the printf(), that memory could have been reallocated to a completely different object (like attacker-controlled input). The program uses the old pointer, leading to data corruption or code execution.

4. The Off-By-One

#include <stdio.h>

int main() {
    int scores[10];
    for (int i = 0; i <= 10; i++) {
        scores[i] = 100;
    }
    printf("Done!\n");
    return 0;
}
Program 8: 4. The Off-By-One
Reveal Vulnerability Static Array Overflow (Out-Of-Bounds Write). An array of size 10 has indices 0 through 9. The loop condition i <= 10 executes for index 10, overwriting whatever memory sits immediately after the array on the stack.

5. The Echo

#include <stdlib.h>

void cleanup(char *ptr) {
    if (ptr) {
        free(ptr);
    }
}

int main() {
    char *buffer = malloc(256);
    cleanup(buffer);
    // ... error occurs ...
    cleanup(buffer);
    return 0;
}
Program 9: 5. The Echo
Reveal Vulnerability Double Free. Calling free() on the same pointer twice corrupts the heap allocator's internal linked lists (the freelist). Attackers can manipulate this to overwrite arbitrary memory locations.

6. The Unfiltered Echo

#include <stdio.h>

void log_input(char *user_input) {
    printf(user_input);
}

int main() {
    log_input("%x %x %x\n");
    return 0;
}
Program 10: 6. The Unfiltered Echo
Reveal Vulnerability Format String Vulnerability. If the user inputs %x %x %x, printf will pop values off the stack and print them, leaking sensitive data. Worse, if they input %n, they can write data to arbitrary memory addresses!

Extended: The Unfiltered Echo

#include<stdio.h>
#include<stdlib.h>
void log_input(char *user_input) {
    printf("userinput = %d\n", *(int *)user_input);
}

int main() {
	char ptr[] = {'a'};
	log_input(ptr);
}
Program 10: Extended: The Unfiltered Echo

7. The Missing Check

#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int updated;
} Config;

Config* get_config() {
    return NULL; // Fails to get config
}

void update_config(Config *cfg) {
    cfg->updated = 1;
}

int main() {
    Config *cfg = get_config(); // Returns NULL
    update_config(cfg);
    return 0;
}
Program 11: 7. The Missing Check
Reveal Vulnerability Null Pointer Dereference. If get_config() fails and returns NULL, the program attempts to write to memory address 0. This instantly crashes the program (Denial of Service).

8. The Dirty Laundry

#include <stdio.h>

int check_secret_key() {
    return 0; // Wrong key
}

void check_auth() {
    int is_admin; // Not initialized
    if (check_secret_key() == 1) {
        is_admin = 1;
    }
    if (is_admin) {
        printf("Access Granted.\n");
    }
}

int main() {
    check_auth();
    return 0;
}
Program 12: 8. The Dirty Laundry
Reveal Vulnerability Uninitialized Variable. Local variables in C are not automatically set to zero. is_admin contains whatever garbage data was left on the stack from previous function calls. If that garbage data happens to be non-zero, the attacker bypasses authentication!

9. The Short Request

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main() {
    char *src = "Super Secret Password";
    char *dest = malloc(10);
    strcpy(dest, src);
    printf("Copied: %s\n", dest);
    return 0;
}
Program 13: 9. The Short Request
Reveal Vulnerability Heap Buffer Overflow. We allocated 10 bytes on the heap, but strcpy copies until it hits a null terminator. It will copy all 22 bytes of the source string, overwriting 12 bytes of adjacent heap memory.

10. The Silent Killer

#include <stdlib.h>

int user_aborted() {
    return 1; // User always aborts
}

void handle_request() {
    char *session_data = malloc(4096);
    if (user_aborted()) {
        return; // Early exit (Memory Leak)
    }
    free(session_data);
}

int main() {
    handle_request();
    return 0;
}
Program 14: 10. The Silent Killer
Reveal Vulnerability Memory Leak. If user_aborted() is true, the function returns early and skips the free() call. Every time an attacker triggers this condition, the server permanently loses 4KB of RAM until it crashes completely.

Top 5 Multithreading Vulnerabilities in C/C++

As applications scale, developers turn to multithreading. However, manual memory management combined with concurrency creates some of the most difficult-to-debug vulnerabilities in computing.

11. The Data Race

#include <stdio.h>
#include <pthread.h>

int counter = 0;

void* increment(void* arg) {
    for (int i = 0; i < 100000; i++) {
        counter++; // Data race! Read, Add, Write
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("Expected 200000, got: %d\n", counter);
    return 0;
}
Program 15: 11. The Data Race
Reveal Vulnerability Data Race. counter++ is not an atomic operation. Multiple threads fetch the same value, increment it, and overwrite each other, causing lost updates.

12. The Deadlock Trap

#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

pthread_mutex_t lock1 = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t lock2 = PTHREAD_MUTEX_INITIALIZER;

void* thread_a(void* arg) {
    pthread_mutex_lock(&lock1);
    sleep(1); // Simulate work
    pthread_mutex_lock(&lock2); // Waiting for lock2...
    
    printf("Thread A complete.\n");
    pthread_mutex_unlock(&lock2);
    pthread_mutex_unlock(&lock1);
    return NULL;
}

void* thread_b(void* arg) {
    pthread_mutex_lock(&lock2);
    sleep(1); // Simulate work
    pthread_mutex_lock(&lock1); // Waiting for lock1...
    
    printf("Thread B complete.\n");
    pthread_mutex_unlock(&lock1);
    pthread_mutex_unlock(&lock2);
    return NULL;
}

int main() {
    pthread_t t1, t2;
    printf("Starting threads... This will freeze!\n");
    pthread_create(&t1, NULL, thread_a, NULL);
    pthread_create(&t2, NULL, thread_b, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}
Program 16: 12. The Deadlock Trap
Reveal Vulnerability Deadlock. Thread A locks 1 and waits for 2. Thread B locks 2 and waits for 1. Neither can proceed, and the application freezes permanently.

13. The Time-of-Check Trap (TOCTOU)

#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

int item_stock = 1; // Only 1 item left!

void* buy_item(void* arg) {
    if (item_stock > 0) { // Time of Check
        // Context switch happens here!
        sleep(1); 
        item_stock--; // Time of Use
        printf("Purchase successful! Stock left: %d\n", item_stock);
    } else {
        printf("Out of stock!\n");
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, buy_item, NULL);
    pthread_create(&t2, NULL, buy_item, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}
Program 17: 13. The TOCTOU Trap
Reveal Vulnerability Time-of-Check to Time-of-Use. Both threads check the stock simultaneously. Since they both see stock > 0, they both proceed to buy it, resulting in a negative inventory.

14. The Concurrent Ghost (Use-After-Free)

#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <unistd.h>
#include <string.h>

char *shared_msg;

void* background_reader(void* arg) {
    sleep(1); // Wait a moment
    // Crashes or prints garbage because the memory was freed!
    printf("Reader sees: %s\n", shared_msg); 
    return NULL;
}

int main() {
    shared_msg = malloc(50);
    strcpy(shared_msg, "Top Secret Data");

    pthread_t t1;
    pthread_create(&t1, NULL, background_reader, NULL);
    
    // Main thread decides to free the data early
    free(shared_msg);
    
    pthread_join(t1, NULL);
    return 0;
}
Program 18: 14. The Concurrent Ghost
Reveal Vulnerability Concurrent Use-After-Free. Multithreading vastly complicates memory management. The main thread frees the pointer while a background thread is still relying on it.

15. The Missing Unlock

#include <stdio.h>
#include <pthread.h>

pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
int count = 0;

void process_data(int input) {
    pthread_mutex_lock(&lock);
    
    if (input < 0) {
        printf("Error: Invalid input.\n");
        return; // Vulnerability: Early return misses the unlock!
    }
    
    count += input;
    pthread_mutex_unlock(&lock);
}

void* thread_func(void* arg) {
    process_data(-1); // Triggers error path
    printf("Thread finished.\n");
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, thread_func, NULL);
    pthread_create(&t2, NULL, thread_func, NULL); // Will hang forever
    
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}
Program 19: 15. The Missing Unlock
Reveal Vulnerability Missing Mutex Unlock. C does not automatically clean up locks on return. If an error condition causes an early return, the mutex remains locked forever, blocking all other threads that try to acquire it.
