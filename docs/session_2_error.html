Session 2.9

Error Handling

Overview & Types of Errors

Rust groups errors into two major categories: recoverable and unrecoverable errors. Rust doesn't have exceptions like Java or Python. Instead, it has the type Result<T, E> for recoverable errors and the panic! macro for unrecoverable errors.

💡 Compiler-Driven Development (CDD)

Beginners often feel the Rust compiler is "fighting" them. To succeed, you must shift your mindset: treat the compiler as a strict but incredibly helpful pair programmer. When you get a wall of red text, don't panic. Read it carefully. Look for the help: and note: tags. Rust's compiler is famous for actually providing the exact code snippet required to fix your error 90% of the time. Let the compiler drive your development!

Example 1: Unrecoverable Errors (panic!)

View C/C++ Buggy Code 

// C Error Handling: Silent Failures
void read_config() {
    // fopen returns NULL if the file doesn't exist
    FILE *file = fopen("secrets.txt", "r");
    
    // BUG: Developer forgot to check for NULL.
    // fread will attempt to read from address 0x0 and crash.
    char buffer[100];
    fread(buffer, 1, 100, file); 
}
                        
fn main() {
    // This will immediately stop execution and print an error message.
    panic!("Crash and burn!");
}

Why: When a panic occurs, the program stops, cleans up its memory, and exits. Use this when the program enters a state it absolutely cannot recover from (like an out-of-bounds array access).

Example 2: Recoverable Errors (Result Enum)

use std::fs::File;

fn main() {
    let file_result = File::open("hello.txt");

    let file = match file_result {
        Ok(file) => file,
        Err(error) => panic!("Problem opening the file: {:?}", error),
    };
}

Output (if file missing): thread 'main' panicked at 'Problem opening the file: Os { code: 2, kind: NotFound, message: "No such file or directory" }'

Why: File::open returns a Result type, which is an enum with two variants: Ok (contains the file handle) and Err (contains the error details). We use a match statement to handle both possibilities securely, ensuring we never accidentally operate on a failed file handle.

Example 3: The `?` Operator Shortcut

use std::fs::File;
use std::io::Read;
use std::io::Error;

fn read_username() -> Result<String, Error> {
    let mut username = String::new();
    // The '?' will return the error to the calling function if File::open fails
    let mut file = File::open("hello.txt")?;
    
    // The '?' will also return the error if read_to_string fails
    file.read_to_string(&mut username)?;
    
    Ok(username)
}

Output: Depends on if the file exists. It returns either Ok(username) or an Err.

Why: The ? operator is placed after a Result value. If the value is Ok, it unpacks the value and continues. If it's an Err, it immediately returns from the whole function, propagating the error up the chain automatically.

C/C++ Error Return Confusion

View C/C++ Ambiguous Returns 

// In C/C++, functions often use a special value (like -1, 0, or NULL) to indicate an error.
#include <stdlib.h>
#include <stdio.h>

void process_input(const char* input) {
    int val = atoi(input);
    // BUG: atoi returns 0 on error! But what if the user actually typed "0"?
    // The developer cannot distinguish between success ("0") and error ("invalid string").
    // This ambiguity leads to severe logic bugs and security flaws.
    if (val == 0) {
        printf("Error or Zero? Who knows!\n");
    }
}

Example 4: The Option Enum (Absence of Data)

To fix the concept of Null pointers, Rust uses the Option<T> enum when a value might be absent. It forces the developer to check for null.

fn find_user(id: i32) -> Option<String> {
    if id == 1 {
        Some(String::from("Alice"))
    } else {
        None // No null pointers here!
    }
}

fn main() {
    let user = find_user(2);
    // You cannot use 'user' directly without explicitly handling the 'None' case.
    // println!("{}", user); // This will not compile!
}

Example 5: Handling Option with `match`

The compiler forces you to handle both the Some and None cases using a match block.

fn main() {
    let user = Some(String::from("Alice"));

    match user {
        Some(name) => println!("Found user: {}", name),
        None => println!("User not found!"),
    }
}

Example 6: Complex Logic with `match` and Result

You can use match to handle specific types of errors gracefully rather than just panicking.

use std::fs::File;
use std::io::ErrorKind;

fn main() {
    // Attempt to open the file
    let file = File::open("config.txt");

    let _config = match file {
        Ok(f) => f,
        Err(error) => match error.kind() {
            // If it doesn't exist, create it!
            ErrorKind::NotFound => match File::create("config.txt") {
                Ok(fc) => fc,
                Err(e) => panic!("Tried to create file but failed: {:?}", e),
            },
            // For any other error (like permissions), panic.
            other_error => panic!("Problem opening the file: {:?}", other_error),
        },
    };
}

Knowledge Check

Question: What does the ? operator do in Rust?

Answer: It propagates errors. It is syntactic sugar that unpacks the value if a Result is Ok, but if it is an Err, it immediately returns that error from the current function up to the caller.
