Exercise 3

Secure Account Access

Mission Briefing: Hackers have been crashing the bank's legacy C++ servers by requesting account indices that don't exist, causing buffer overflows. Your task is to rewrite the account lookup mechanism to securely handle invalid indices without crashing.

Objective

In C, reading past the end of an array causes a buffer overflow. In Rust, standard indexing array[10] will panic and crash the program safely. But we can do better: we can gracefully handle the error without crashing using the Option enum and the .get() method.

Project Code

fn main() {
    let account_balances = [4012, 8933, 1024, 7731];
    
    // Simulate a hacker asking for the 10th account
    let requested_index = 10;
    
    // Using .get() returns an Option (Some(value) or None) 
    // instead of panicking on out-of-bounds access.
    let access_attempt = account_balances.get(requested_index);
    
    match access_attempt {
        Some(balance) => println!("Account Balance retrieved: ${}", balance),
        None => println!("SECURITY ALERT: Invalid account access attempted!"),
    }
}
Program 28: Project Code

How to Run

Run cargo run. You should see the security alert triggered instead of a program crash. Change requested_index to 2 and run it again to see the success case.

Enhancement Challenges

Modify the code above to accomplish the following:

  1. Dynamic Input: Use std::io::stdin() to ask the user to type in an index at runtime, rather than hardcoding 10. (You will need to parse the string into a usize).
  2. Safe Loop: Wrap the logic in a loop so that if the user enters an invalid index, it prints the alert and asks them to try again, only exiting when they retrieve a valid code.
  3. Vector Push: Change the fixed-size array to a dynamic Vec<i32>. Add a feature allowing the user to push a new code to the end of the vector, demonstrating that vectors safely manage heap allocations.
