Session 1.1

Memory Structure

Process Memory Segments

When an operating system runs a program, it allocates an isolated block of virtual memory for that process. This memory is divided into distinct segments, each serving a specific purpose:

  • Text (Code) Segment: Read-only memory where the compiled machine instructions live. Making this read-only prevents attackers from modifying the running code.
  • Data Segment: Stores global and static variables that are explicitly initialized by the developer (e.g., int count = 5;).
  • BSS Segment: Stores global and static variables that are uninitialized (e.g., int total;). The OS zeroes this out before execution.
  • Heap: Dynamic memory allocated at runtime (e.g., via malloc()). Grows upwards. Used for data whose size isn't known until the program is running.
  • Stack: Fast, static memory for local function variables and call frames. Grows downwards. Automatically managed as functions are called and return.

How Memory Works in C/C++

To understand why traditional systems languages are prone to vulnerabilities, we must first understand how they structure and manage memory. Programs divide memory into several segments, but the two most important for developers are the Stack and the Heap.

The Stack

Fast, highly organized memory used for static data (like local variables and function call frames). Size must be known at compile time. Data is automatically pushed and popped as functions execute.

Example: int count = 5; or char buf[10];

The Heap

Large, unorganized memory pool used for dynamic data (where size can change at runtime). Developers must manually request space (malloc) and manually return it (free).

Example: int* data = malloc(100);

Hardware & OS Memory Protection

Image 1: Hardware & OS Memory Protection

How Protection Works: The OS Kernel is responsible for allocating specific memory segments (like the Stack and Heap) to each running process. However, the OS relies on hardware—specifically the Memory Management Unit (MMU)—to actively monitor and enforce these boundaries at runtime. If a process attempts to read or write data outside of its allocated segment (e.g., due to a buffer overflow or dangling pointer), the MMU hardware intercepts the invalid access and throws a hardware exception. The OS Kernel catches this exception and immediately kills the offending process with a Segmentation Fault (Segfault) to prevent data leakage or corruption.

Manual Memory Management (C Example)

When you use the Heap in C, you take on 100% of the responsibility for that memory. Let's look at a standard example using buffers, malloc, and free.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void process_data() {
    // 1. ALLOCATION: Requesting a buffer of 100 bytes on the Heap
    char *buffer = (char *)malloc(100 * sizeof(char));
    
    // Check if allocation failed (often forgotten in real code!)
    if (buffer == NULL) {
        return; 
    }

    // 2. USAGE: Writing data into the buffer
    strcpy(buffer, "Secret Security Data");
    printf("Data: %s\n", buffer);

    // 3. DEALLOCATION: Giving the memory back to the OS
    free(buffer);

    // DANGER: The pointer 'buffer' still holds the memory address, 
    // even though we don't own it anymore. It is now a "Dangling Pointer".
}
Program 3: Manual Memory Management (C Example)

The Weak Links

The code above looks simple, but it relies entirely on the developer perfectly tracking the lifecycle of buffer. If any of the following occur, you have a critical security vulnerability:

  • Forget to call free(): Memory Leak. If this happens in a loop, the server will crash from Out of Memory (OOM).
  • Write more than 100 bytes: Heap Buffer Overflow. You corrupt adjacent memory, allowing attackers to inject code.
  • Call free() twice: Double Free. Corrupts the memory allocator data structures, often leading to code execution.
  • Use buffer after freeing it: Use-After-Free (UAF). The memory might have been reassigned to something else, like an authentication token, which the attacker can now manipulate.

Knowledge Check

Question: Which memory error occurs if you forget to write free(buffer) inside a loop?

Answer: A Memory Leak. The allocated memory on the Heap is never returned to the OS. Over time, the program will continually request new blocks until it consumes all available RAM and crashes (Out of Memory).
