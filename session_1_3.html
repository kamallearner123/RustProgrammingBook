Session 1.3

C/C++ in the Wild

C and C++ are the backbone of modern computing, but their unmanaged memory model creates a playground for hackers. Before seeing how Rust solves these issues, let's test your ability to spot vulnerabilities in standard C code.

Image 2: C/C++ in the Wild

(Please ensure 'c_cpp_wild.png' is in your project folder)

Vulnerability Challenge

Look at the 10 code snippets below. Can you guess what the vulnerability is before revealing the answer?

1. The Classic Mistake

void get_password() {
    char password[16];
    printf("Enter password: ");
    gets(password);
}
Program 5: 1. The Classic Mistake
Reveal Vulnerability Stack Buffer Overflow. The gets() function reads from standard input until it sees a newline, completely ignoring the 16-byte limit of the buffer. An attacker can input 500 characters and overwrite the function's return address, taking control of the program.

2. The Math Trap

void transfer_funds(unsigned int amount) {
    unsigned int balance = 100;
    if (balance - amount >= 0) { // Check if we have enough
        balance -= amount;
        printf("Transfer successful!\n");
    }
}
Program 6: 2. The Math Trap
Reveal Vulnerability Integer Underflow / Logical Flaw. Because balance and amount are unsigned int, they can never be negative. If amount is 500, 100 - 500 wraps around to a massive positive number (e.g., 4294966896). The >= 0 check is always true!

3. The Ghost Pointer

char *user = malloc(100);
strcpy(user, "admin");
free(user);

// ... later in the code ...
printf("Welcome, %s\n", user);
Program 7: 3. The Ghost Pointer
Reveal Vulnerability Use-After-Free (UAF). The memory was freed and given back to the OS. Between the free() and the printf(), that memory could have been reallocated to a completely different object (like attacker-controlled input). The program uses the old pointer, leading to data corruption or code execution.

4. The Off-By-One

int scores[10];
for (int i = 0; i <= 10; i++) {
    scores[i] = 100;
}
Program 8: 4. The Off-By-One
Reveal Vulnerability Static Array Overflow (Out-Of-Bounds Write). An array of size 10 has indices 0 through 9. The loop condition i <= 10 executes for index 10, overwriting whatever memory sits immediately after the array on the stack.

5. The Echo

void cleanup(char *ptr) {
    if (ptr) {
        free(ptr);
    }
}
// ...
char *buffer = malloc(256);
cleanup(buffer);
// ... error occurs ...
cleanup(buffer);
Program 9: 5. The Echo
Reveal Vulnerability Double Free. Calling free() on the same pointer twice corrupts the heap allocator's internal linked lists (the freelist). Attackers can manipulate this to overwrite arbitrary memory locations.

6. The Unfiltered Echo

void log_input(char *user_input) {
    printf(user_input);
}
Program 10: 6. The Unfiltered Echo
Reveal Vulnerability Format String Vulnerability. If the user inputs %x %x %x, printf will pop values off the stack and print them, leaking sensitive data. Worse, if they input %n, they can write data to arbitrary memory addresses!

7. The Missing Check

void update_config(Config *cfg) {
    cfg->updated = 1;
}

int main() {
    Config *cfg = get_config(); // Might return NULL
    update_config(cfg);
}
Program 11: 7. The Missing Check
Reveal Vulnerability Null Pointer Dereference. If get_config() fails and returns NULL, the program attempts to write to memory address 0. This instantly crashes the program (Denial of Service).

8. The Dirty Laundry

void check_auth() {
    int is_admin; // Not initialized
    if (check_secret_key() == 1) {
        is_admin = 1;
    }
    if (is_admin) {
        printf("Access Granted.\n");
    }
}
Program 12: 8. The Dirty Laundry
Reveal Vulnerability Uninitialized Variable. Local variables in C are not automatically set to zero. is_admin contains whatever garbage data was left on the stack from previous function calls. If that garbage data happens to be non-zero, the attacker bypasses authentication!

9. The Short Request

char *src = "Super Secret Password";
char *dest = malloc(10);
strcpy(dest, src);
Program 13: 9. The Short Request
Reveal Vulnerability Heap Buffer Overflow. We allocated 10 bytes on the heap, but strcpy copies until it hits a null terminator. It will copy all 22 bytes of the source string, overwriting 12 bytes of adjacent heap memory.

10. The Silent Killer

void handle_request() {
    char *session_data = malloc(4096);
    if (user_aborted()) {
        return; // Early exit
    }
    free(session_data);
}
Program 14: 10. The Silent Killer
Reveal Vulnerability Memory Leak. If user_aborted() is true, the function returns early and skips the free() call. Every time an attacker triggers this condition, the server permanently loses 4KB of RAM until it crashes completely.
