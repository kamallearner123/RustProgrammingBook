Session 1.4

Tools and Practices in C/C++

Because C and C++ do not protect against memory vulnerabilities at the language level, the industry has spent decades building external tools, linters, and strict coding guidelines to try and patch the gaps. Here are the most prominent methods.

1. Valgrind (Memcheck)

Valgrind is a dynamic binary instrumentation framework. Its most famous tool, Memcheck, runs your compiled C/C++ binary in a simulated environment to track every single memory allocation and access at runtime.

Installation

# Ubuntu / Debian
sudo apt-get install valgrind

# macOS (using Homebrew)
brew install valgrind
Program 15: Installation

Example Program (Memory Leak)

#include <stdlib.h>

void leak_memory() {
    int* ptr = malloc(10 * sizeof(int));
    // Memory is never freed!
}

int main() {
    leak_memory();
    return 0;
}
Program 16: Example Program (Memory Leak)

How to Compile and Run

Always compile with the -g flag to include debugging symbols, which allows Valgrind to show exact line numbers in its report.

$ gcc -g leak.c -o leak_app
$ valgrind --leak-check=full ./leak_app

2. Helgrind

Helgrind is another Valgrind tool specifically designed to detect data races in multithreaded C/C++ programs that use POSIX pthreads.

Installation

Helgrind is included automatically when you install the standard Valgrind package (see above).

Example Program (Data Race)

#include <pthread.h>
#include <stdio.h>

int shared_counter = 0;

void* increment(void* arg) {
    for(int i = 0; i < 10000; i++) {
        shared_counter++; // Data race! No mutex lock used.
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}

How to Compile and Run

$ gcc -g -pthread datarace.c -o datarace_app
$ valgrind --tool=helgrind ./datarace_app

3. Address Sanitizer (ASan)

Built directly into modern compilers like GCC and Clang, ASan instruments memory accesses during the compilation phase to detect out-of-bounds accesses and use-after-free bugs. It is much faster than Valgrind.

Installation

ASan is built into GCC (v4.8+) and Clang (v3.1+). If you have a modern C compiler installed, you already have ASan. On Linux, you may need the specific ASan library package:

# Ubuntu / Debian
sudo apt-get install libasan6
Program 22: Installation

Example Program (Use-After-Free)

#include <stdlib.h>
#include <stdio.h>

int main() {
    int *array = malloc(100 * sizeof(int));
    free(array);
    
    // ERROR: Using memory after it has been freed
    return array[5]; 
}
Program 23: Example Program (Use-After-Free)

How to Compile and Run

You must compile the program with the -fsanitize=address flag. Then simply run the binary normally.

$ gcc -fsanitize=address -g uaf.c -o uaf_app
$ ./uaf_app

The Rust Paradigm Shift

Instead of relying on heavy runtime tools (Valgrind), secondary compiler flags (ASan), or restrictive paper rulebooks (MISRA), Rust builds all of these protections directly into the default compiler. If your code has a data race or a use-after-free, it simply will not compile.
