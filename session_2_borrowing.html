Session 2.4

Borrowing

Overview & Syntax

If we had to transfer ownership (move) every time we passed a variable to a function, programming in Rust would be very tedious. Instead, Rust allows you to borrow a value using a reference. Borrowing allows you to access data without taking ownership of it.

We use the ampersand symbol & to create a reference (borrow) to a value.

Example 1: Passing by Borrow (Reference)

View C/C++ Buggy Code 

// C Use-After-Free (UAF) Vulnerability
void process_user() {
    char *user = malloc(20);
    strcpy(user, "admin");
    free(user); // Memory returned to OS
    
    // BUG: The pointer still holds the address.
    // If an attacker allocates memory here, they control 'user'.
    printf("Processing: %s\n", user); 
}
                        
fn calculate_length(s: &String) -> usize {
    s.len()
} // Here, s goes out of scope. But because it does not have ownership of what it refers to, it is not dropped.

fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1); // We pass a reference, not the value

    println!("The length of '{}' is {}.", s1, len);
}

Why: The &s1 syntax lets us create a reference that refers to the value of s1 but does not own it. Because it does not own it, the value it points to will not be dropped when the reference stops being used. s1 is still valid after the function call.

Example 2: Error Modifying a Borrowed Value

fn change(some_string: &String) {
    some_string.push_str(", world"); // ERROR: cannot borrow as mutable
}

fn main() {
    let s = String::from("hello");
    change(&s);
}

Error Explanation: Just as variables are immutable by default, so are references. We are not allowed to modify something we have a borrowed reference to. This prevents unexpected data modification by functions that supposedly just needed to "look" at the data.

Example 3: Mutable Borrows

fn change(some_string: &mut String) {
    some_string.push_str(", world");
}

fn main() {
    let mut s = String::from("hello");
    change(&mut s);
    println!("{}", s);
}

Why: We can explicitly create a mutable reference using &mut. Notice three things changed: 1) the variable itself is mut s, 2) we pass &mut s to the function, and 3) the function signature accepts &mut String. This clearly flags at every level that modification is happening.

Knowledge Check (MCQ)

Question: What happens to the original value when its reference goes out of scope?

  1. The original value is dropped and freed.
  2. Nothing. The reference didn't own the data, so the data persists.
  3. The original value becomes mutable.
  4. A memory leak occurs.

Answer: B. Since the reference does not own the data, the data is left completely intact when the reference's scope ends.
