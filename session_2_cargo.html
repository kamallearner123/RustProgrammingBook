Session 2.8

Cargo Basics

Overview & Concepts

Cargo is Rust’s build system and package manager. It handles everything from creating new projects, downloading libraries (called "crates" in Rust), building your code, and running your tests.

Example 1: Creating a Project

$ cargo new security_tool
$ cd security_tool
$ ls
Cargo.toml  src/

Output: A new folder containing Cargo.toml and a src directory with main.rs.

Why: Cargo.toml is the configuration file for your project (written in TOML). It tracks your project's name, version, and dependencies. The src folder is where all your Rust code belongs.

Example 2: Adding Dependencies

Modify your Cargo.toml to include a third-party library, like the popular random number generator rand:

[dependencies]
rand = "0.8.5"

Then run the build command:

$ cargo build

Output: Cargo will reach out to crates.io, download the rand crate and all its dependencies, and compile them alongside your code.

Why: This standardized package management makes sharing code across the Rust ecosystem incredibly easy and secure. Cargo creates a Cargo.lock file to ensure reproducible builds.

Example 3: Checking and Running

$ cargo check
$ cargo run

Output: cargo check quickly analyzes your code to ensure it compiles without producing an executable. cargo run compiles the code and executes the resulting binary immediately.

Why: Running cargo check is much faster than a full compile, making it ideal to run frequently while writing code to catch syntax and type errors early.

Knowledge Check (MCQ)

Question: What is the main difference between cargo build and cargo check?

  1. cargo check only downloads dependencies.
  2. cargo check verifies that the code compiles but skips generating the executable binary to save time.
  3. cargo build runs the tests automatically.
  4. There is no difference; they are aliases.

Answer: B. cargo check is used during development for fast feedback on compiler errors.
