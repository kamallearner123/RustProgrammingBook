Session 2.3

Ownership

Overview & Rules

Ownership is Rust’s most unique feature and has deep implications for the rest of the language. It enables Rust to make memory safety guarantees without needing a garbage collector.

The 3 Rules of Ownership:
  1. Each value in Rust has an owner.
  2. There can only be one owner at a time.
  3. When the owner goes out of scope, the value will be dropped (memory freed).

⚠️ C/C++ Developer Trap: Passing by Value "Moves" the Data

In C/C++, if you pass a struct to a function, the compiler silently copies the memory. In Rust, if you pass a String or a custom struct into a function, ownership is moved. The original variable instantly becomes invalid. You cannot use it again unless the function returns ownership back to you. This guarantees there is only ever one owner responsible for freeing the memory.

Example 1: Variable Scope and Drop

View C/C++ Buggy Code 

// C manual memory management leads to Double Free bugs
void cleanup() {
    char *auth_token = malloc(64);
    // ... use token ...
    free(auth_token);
    
    // ... complex logic ...
    
    // BUG: Freeing the same memory twice corrupts the allocator, 
    // often leading to Remote Code Execution (RCE).
    free(auth_token); 
}
                        
fn main() {
    {                      // s is not valid here, it’s not yet declared
        let s = "hello";   // s is valid from this point forward
        println!("{s}");
    }                      // this scope is now over, and s is no longer valid
}

Why: When a variable like s goes out of scope at the closing curly brace }, Rust automatically calls a special function called drop to free the memory. You never have to call free() manually.

Example 2: The "Move" Semantics (Error Example)

fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // Ownership of the string moves from s1 to s2

    println!("{}, world!", s1); // ERROR: borrow of moved value: `s1`
}

Error Explanation: Because Rust must ensure there is only one owner at a time, when we assign s1 to s2, the pointer to the heap data is transferred to s2, and s1 is marked as invalid. This prevents the "Double Free" vulnerability when both variables eventually go out of scope. s1 was "moved".

Example 3: Deep Copying (Cloning)

fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone(); // Create a full copy of the heap data

    println!("s1 = {}, s2 = {}", s1, s2);
}

Why: If we deeply want to copy the data on the heap (not just the pointer), we use a method called clone. This leaves s1 as the owner of the first chunk of memory, and s2 as the owner of an entirely new, separate chunk of memory containing the same characters. Both are valid.

Knowledge Check

Question: What happens when you assign a variable pointing to heap memory (like a String) to another variable in Rust?

Answer: Ownership is moved to the new variable, and the old variable becomes invalid. This is completely different from C/C++ (where both point to the same memory, risking double-free) or Java/Python (where both point to the same memory and rely on garbage collection). Rust moves it to prevent memory corruption at compile time.
