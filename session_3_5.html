Exercise 5

Audit Logger

Mission Briefing: The bank requires a secure audit log for regulatory compliance. However, reading from and writing to the filesystem is a notorious source of bugs (e.g., disk full, permission denied). You must build a secure file reader that degrades gracefully on failure instead of causing a Denial of Service (DoS) crash.

Objective

Reading from the filesystem is a notorious source of bugs. The file might not exist, permissions might be denied, or the disk might be full. You will learn to handle these I/O operations safely without causing a Denial of Service (DoS) crash.

Project Code

use std::fs::File;
use std::io::{self, Read};

fn read_config(filename: &str) -> Result<String, io::Error> {
    let mut file = File::open(filename)?; // ? propagates error if file is missing
    let mut contents = String::new();
    file.read_to_string(&mut contents)?;
    Ok(contents)
}

fn main() {
    // Attempt to read a config file that doesn't exist yet
    match read_config("bank_config.txt") {
        Ok(config) => println!("Config loaded safely:\n{}", config),
        Err(e) => {
            // Check the specific kind of error
            if e.kind() == io::ErrorKind::NotFound {
                println!("Notice: Config file not found. Using secure default vault settings.");
            } else {
                println!("Critical Error reading config: {}", e);
            }
        }
    }
}
Program 30: Project Code

How to Run

Run cargo run. The program will gracefully detect the missing file and fallback to default settings. Now, create a file named security_config.txt in the project root, add some text, and run it again!

Enhancement Challenges

Modify the code above to accomplish the following:

  1. Auto-Creation: If the file is not found, use File::create to generate a default bank_config.txt with some standard text, instead of just printing a notice.
  2. Appending Data: Import std::fs::OpenOptions and write a new function that appends a timestamped security log entry to a file named audit.log without overwriting existing contents.
  3. Parse the Config: Assuming the config file contains key-value pairs (e.g., port=8080), write logic to parse the file line-by-line and load the variables into a HashMap.
