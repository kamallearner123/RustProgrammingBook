Exercise 6

Global Vault Total

Mission Briefing: The bank processes thousands of deposits simultaneously. The legacy C++ system suffered from catastrophic Data Races where simultaneous deposits overwrote each other, losing money! You must use Rust's concurrency primitives to build a mathematically accurate, thread-safe vault counter.

Objective

Remember the C program that produced data races? Rust refuses to compile code that shares mutable state across threads without proper synchronization. In this exercise, you'll use an Arc (Atomic Reference Counted pointer) and a Mutex to safely increment a counter across 10 concurrent threads.

Project Code

use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    // Arc allows safe sharing of ownership across threads
    // Mutex ensures only one thread can modify the vault at a time
    let vault_total = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    // Simulate 10 bank branches processing deposits
    for _ in 0..10 {
        let vault_clone = Arc::clone(&vault_total);
        
        let handle = thread::spawn(move || {
            for _ in 0..100_000 {
                // We MUST acquire the lock before accessing the data
                // If another thread has it, we wait here.
                let mut num = vault_clone.lock().unwrap();
                *num += 1; // Deposit $1
            } // Lock is automatically released here
        });
        
        handles.push(handle);
    }

    // Wait for all branches to finish
    for handle in handles {
        handle.join().unwrap();
    }

    println!("Final Vault Total: ${}", *vault_total.lock().unwrap());
}
Program 31: Project Code

How to Run

Run cargo run. Unlike C, this will print exactly 1,000,000 every single time. Try removing the Mutex and passing a standard reference into the thread—the compiler will instantly throw an error to prevent the data race!

Enhancement Challenges

Modify the code above to accomplish the following:

  1. Poisoned Mutex: Intentionally add a if *num == 50000 { panic!("Crash!"); } block inside the loop. Observe how Rust "poisons" the Mutex, preventing other threads from accessing potentially corrupted data, and then figure out how to recover from a poisoned Mutex.
  2. Read-Write Locks: Change Mutex to RwLock. This allows multiple threads to read the value simultaneously, but only one to write. Create 5 threads that only read the value, and 5 that write to it.
  3. Atomic Types: Because our data is just a simple integer, using a Mutex is overkill. Replace Arc<Mutex<i32>> with Arc<AtomicI32> (from std::sync::atomic) and use the .fetch_add() method. Compare the performance!
