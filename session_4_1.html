Session 4.1

Rust in Automotive & SDVs

The Software-Defined Vehicle (SDV) Era

The automotive industry is undergoing a massive transformation. Modern cars are rolling datacenters. With features like Advanced Driver Assistance Systems (ADAS), infotainment, and autonomous driving algorithms running concurrently, a single memory corruption bug in a braking system or CAN bus parser can literally cost lives.

Why C/C++ is No Longer Enough

Historically, ECUs (Electronic Control Units) were programmed in C using MISRA guidelines. However, as compute architecture shifts from 100+ isolated microcontrollers to a few high-powered centralized servers (Zone Controllers), the complexity of data sharing skyrockets. MISRA C cannot mathematically guarantee the absence of race conditions in highly concurrent SDV platforms—but Rust can.

Industry Adoption & Safety Certification
  • Ferrocene (ISO 26262): Ferrous Systems successfully qualified the Ferrocene Rust compiler for ASIL-D (Automotive Safety Integrity Level D), the highest classification of injury risk.
  • AUTOSAR Integration: The standard automotive software architecture (AUTOSAR) is officially adding Rust support to replace legacy C/C++ safety critical components.
  • Major OEMs: Volvo, GM, and Ford are actively transitioning new vehicle architectures to Rust to ensure memory safety at 120mph.

Tutorial Highlight: Secure CAN Bus Parser

Writing a safe CAN frame parser in Rust ensures that malformed packets injected by hackers via Bluetooth or OBD-II ports cannot cause a buffer overflow in the vehicle's telemetry unit.

struct CanFrame { id: u32, data: [u8; 8] }

// Rust guarantees we can never read past the 8th byte!
// Returns Option::None if the ID is incorrect, preventing undefined behavior.
fn parse_engine_temp(frame: &CanFrame) -> Option<u8> {
    if frame.id == 0x1A4 {
        Some(frame.data[2]) // Safe array access
    } else { 
        None 
    }
}
