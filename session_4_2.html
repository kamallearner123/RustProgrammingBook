Session 4.2

Embedded Systems & IoT

No OS? No Problem.

Rust is uniquely positioned to dominate the embedded space. Unlike Python or Java, Rust does not require a garbage collector or a heavy runtime. By adding the #![no_std] attribute to a Rust program, you strip away the standard library, allowing Rust to run directly on "bare-metal" microcontrollers with only a few kilobytes of RAM.

The Embassy Framework

Historically, embedded systems used RTOS (Real-Time Operating Systems) written in C, which relied on error-prone threads and mutexes. Today, Rust's Embassy framework uses Rust's native async/await syntax to handle hardware interrupts and timers with zero allocations and mathematical safety.

IoT Security Revolution

IoT devices are notorious for being compromised by simple buffer overflows (e.g., the Mirai Botnet). Rust's strict compile-time checks eliminate these network-facing vulnerabilities entirely. An IoT smart plug written in Rust is immune to 70% of the exploits that plague C-based devices.

Tutorial Highlight: Blinking an LED safely

Using the Hardware Abstraction Layer (HAL), we can ensure pins are configured correctly at compile-time.

#![no_std]
#![no_main]

use defmt_rtt as _;
use embassy_executor::Spawner;
use embassy_nrf::gpio::{Level, Output, OutputDrive};

#[embassy_executor::main]
async fn main(_spawner: Spawner) {
    let p = embassy_nrf::init(Default::default());
    
    // Type-state programming: pin changes type to Output
    let mut led = Output::new(p.P0_13, Level::Low, OutputDrive::Standard);

    loop {
        led.set_high();
        embassy_time::Timer::after_millis(500).await;
        led.set_low();
        embassy_time::Timer::after_millis(500).await;
    }
}
